03 / The whole foundation

The workspace is
only the beginning.

The kit includes the application and the operational pieces around it. A practical starting point for a technical operator who wants to run and maintain their own AI workspace.

A workspace you can read at a glance

Task history, execution traces, search, filters and provider-reported usage. Dark and light themes, keyboard navigation and responsive layouts.

A worker that saves the work

PostgreSQL-backed tasks, cancellation, linked retries and saved outputs. Interrupted work is surfaced for review instead of silently replayed.

Access with explicit permissions

Operator sign-in, revocable API tokens, an access audit trail and private network defaults. Optional HTTPS and Tailscale Serve configuration.

A recovery path from day one

Verified PostgreSQL archives, a daily backup timer and optional rclone copies. A restore procedure for a clean workspace, with integrity checks.

Connections beyond the dashboard

A scoped task API, local MCP bridge and Python client example. Connect your own tools to the same task workspace.

Source, setup and operating guides

Docker Compose configuration, installation and update scripts, documentation, acceptance tests and a release packager with checksums.

A few good questions

Know what
you’re building on.

Who is Agent Kit for?

A developer, builder or technical operator comfortable administering a Linux server and Docker. It is designed for one operator and one shared workspace. It is not a hosted service or a multi-tenant team platform.

Does everything run locally?

The application, task queue, documents and stored results run on your host. AI tasks call the OpenAI Responses API, so prompts and relevant document content leave your server. You supply the API key and pay the provider’s model charges separately. A local system check works without a model key.

Is this an OpenClaw installation?

No. The kit includes its own bounded OpenAI Responses worker. It does not install OpenClaw or run OpenClaw agent sessions. External clients can connect through the task API or local MCP bridge where their configuration supports it.

What can the assistant actually do?

It can list and read workspace documents, calculate and save text artifacts. You can inspect its task history, tool calls and results, cancel work and retry a task. It cannot run shell commands, browse the web, send messages or deploy software. AI outputs still need your review.

Is version 2.0 ready for my production server?

Version 2.0 is a release candidate with automated API, browser, recovery and package acceptance checks. Before production use, validate your real model account, target host, HTTPS or Tailscale setup and intended backup storage. The acceptance report separates completed tests from remaining launch checks. Existing v1 users need a separate v2 installation.

What costs and license terms should I expect?

Hosting, model usage, domains and optional offsite storage are separate. Review the included commercial license before purchase or deployment. It allows purchasers to modify and run the kit on servers they own or directly operate, and restricts redistribution of the kit as a standalone product.
