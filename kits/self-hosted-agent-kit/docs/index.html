The Problem We Solved
Every developer and team building autonomous agents hits the same wall: running scripts on local laptops fails the moment sleep mode triggers, paid cloud agent platforms cost hundreds monthly, and raw VPS setups lack database isolation, automated watchdog healing, and safety guardrails against accidental catastrophic shell wipes.

Deployment

5-Minute VPS Quickstart

Deploy your complete autonomous agent stack to any fresh Ubuntu or Debian VPS in under 5 minutes with automated provisioning.

✨
Hardware Requirements
Minimum: 1 vCPU, 1 GB RAM, 15 GB SSD (Ubuntu 22.04 or 24.04 LTS). Recommended: 2 vCPU, 2-4 GB RAM on Hetzner (€3.79/mo) or DigitalOcean ($6/mo).

Method 1: One-Line Remote Installer

SSH into your clean VPS and run the one-line deployment script:

Terminal (Root or Sudo) 
curl -fsSL https://agent.example.com/connect.sh | bash

Method 2: Manual Git / Tarball Setup

If you prefer inspecting every script before running:

bash 
# 1. Download and extract the kit bundle (requires active license key)
curl -fsSL -o self-hosted-agent-kit.zip "https://agent.example.com/api/kit/download?key=YOUR_LICENSE_KEY"
unzip self-hosted-agent-kit.zip -d /opt/agent-stack
cd /opt/agent-stack

# 2. Configure your environment
cp .env.example .env
nano .env  # Enter your DOMAIN, passwords, and optional Telegram bot token

# 3. Execute the automated bootstrap script
chmod +x scripts/*.sh scripts/*.py
sudo ./scripts/setup.sh

# 4. Verify systemd and container status
sudo systemctl status agent-stack.service
docker compose ps

Post-Install Verification

Once started, your operations dashboard is live at your configured domain or Tailscale endpoint. Run the one-line watchdog test to ensure green lights across all four microservices:

bash 
sudo /opt/agent-stack/scripts/watchdog.py

D. OpenAI Agents SDK & Codex (Python)

Dispatch tasks and write results to the self-hosted PostgreSQL memory engine:

agent_openai.py 
import os, json, psycopg2
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))
conn = psycopg2.connect(os.environ.get("DATABASE_URL"))

def run_agent_job(prompt: str):
    with conn.cursor() as cur:
        cur.execute(
            "INSERT INTO agent_tasks (prompt, framework, safety_status) VALUES (%s, %s, %s) RETURNING id;",
            (prompt, "openai", "PASSED")
        )
        task_id = cur.fetchone()[0]
        conn.commit()

    resp = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )
    output = resp.choices[0].message.content

    with conn.cursor() as cur:
        cur.execute(
            "UPDATE agent_tasks SET output = %s, completed_at = NOW() WHERE id = %s;",
            (output, task_id)
        )
        conn.commit()
    return output
Data Engine

PostgreSQL 17 Schema & Models

Pre-initialized database schemas optimized for high-throughput agent logs, JSONB metadata, and vector indexing.

Table: agent_tasks

Records all incoming agent prompts, execution status, guardrail verification, and returned outputs.

PostgreSQL 17 DDL 
CREATE TABLE IF NOT EXISTS agent_tasks (
    id SERIAL PRIMARY KEY,
    prompt TEXT NOT NULL,
    output TEXT,
    safety_status VARCHAR(50) DEFAULT 'PASSED',
    framework VARCHAR(50) DEFAULT 'generic',
    session_id VARCHAR(100),
    metadata JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    completed_at TIMESTAMP WITH TIME ZONE
);

CREATE INDEX IF NOT EXISTS idx_agent_tasks_created_at ON agent_tasks (created_at DESC);
CREATE INDEX IF NOT EXISTS idx_agent_tasks_framework ON agent_tasks (framework);
CREATE INDEX IF NOT EXISTS idx_agent_tasks_safety ON agent_tasks (safety_status);

Table: agent_registry

Maintains live heartbeats and health metrics across multi-agent clusters and external IDE connectors.

PostgreSQL 17 DDL 
CREATE TABLE IF NOT EXISTS agent_registry (
    agent_id VARCHAR(100) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    framework VARCHAR(50) NOT NULL,
    status VARCHAR(50) DEFAULT 'online',
    last_ping TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    metadata JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX IF NOT EXISTS idx_agent_registry_ping ON agent_registry (last_ping DESC);

Extensibility

Extending with Custom Agent Containers

How to build, containerize, and orchestrate custom 24/7 Python, Node.js, or Go worker agents directly within the Docker mesh.

Step 1: Create Your Worker Directory

Create a dedicated directory under agents/my-worker/:

Dockerfile 
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "worker.py"]

Step 2: Add Service to Docker Compose

Edit docker-compose.yml to wire your container into the private network:

docker-compose.yml 
  my-worker:
    build: ./agents/my-worker
    container_name: my-worker-agent
    restart: unless-stopped
    environment:
      - DATABASE_URL=postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres.example.com:5432/${POSTGRES_DB}
      - REDIS_URL=redis://:${REDIS_PASSWORD}@redis.example.com:6379
      - OPENAI_API_KEY=${OPENAI_API_KEY}
    networks:
      - agent-net
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy

Step 3: Launch and Monitor

bash 
docker compose up -d --build my-worker
docker compose logs -f my-worker
Security Engine

ZeroVPS Guardrail Engine

Runtime command interception and abstract syntax tree (AST) blacklisting protecting host VPS stability.

Protected Vectors & Rule Hierarchy

Category Blocked Patterns Action
Root Filesystem Destruction rm -rf /, mkfs.*, dd if=/dev/zero of=/dev/sd* BLOCKED (403)
Resource Exhaustion :(){ :|:& };: (fork bombs), unconstrained heap bombs BLOCKED (403)
Credential Exfiltration Targeting unverified raw IP webhooks, dumping .env BLOCKED (403)
Host Firewall Tampering ufw disable, unverified iptables flushes BLOCKED (403)

Reliability

Automated Watchdog & Telegram Alerts

Background health daemon providing continuous self-healing, process recovery, and push notifications.

Automated Healing Cycle

Every 60 seconds, agent-watchdog.timer executes scripts/watchdog.py:

  1. Pings Docker daemon and checks container states.
  2. Executes SELECT 1 against PostgreSQL inside the private bridge.
  3. Executes PING against Redis.
  4. Checks disk utilization (alerts if / exceeds 85%).
  5. If any container is degraded, triggers up to 3 automatic restarts before paging Telegram.

Disaster Recovery

Nightly Backups & Full Stack Restore

Automated gzip-compressed database snapshots with point-in-time recovery runbooks.

1. Manual Backup On-Demand

bash 
sudo /opt/agent-stack/scripts/backup.sh
# Outputs: /opt/agent-stack/backups/agent-backup-YYYY-MM-DD-HHMM.tar.gz

2. Full Disaster Recovery Restore Procedure

bash 
# 1. Stop agent runtime writes
docker compose stop agent-runtime

# 2. Decompress target backup archive
gunzip -c /opt/agent-stack/backups/postgres_YYYYMMDD_HHMMSS.sql.gz > /tmp/restore_postgres.sql

# 3. Restore PostgreSQL dump
cat /tmp/restore_postgres.sql | docker compose exec -T postgres psql -U ${POSTGRES_USER:-agent} -d ${POSTGRES_DB:-agentdb}
rm -f /tmp/restore_postgres.sql

# 4. Optional: Restore Redis snapshot
# cp /opt/agent-stack/backups/redis_YYYYMMDD_HHMMSS.rdb ./data/redis/dump.rdb

# 5. Restart stack
sudo systemctl restart agent-stack.service
Troubleshooting

Top 10 Buyer Issues & Resolution Playbook

Battle-tested solutions for the most common buyer questions and deployment hiccups.

1. "I cannot connect to PostgreSQL (5432) from my laptop"

Cause: By design, database ports are NOT exposed to 0.0.0.0 on the public internet to prevent brute-force attacks.

Solution: Use an encrypted SSH tunnel:

ssh -L 5432:localhost:5432 user@vps-ip

2. "SSL certificate error / Caddy HTTPS handshake fails"

Cause: ACME challenge cannot reach the server via port 80/443 or Cloudflare is set to flexible mode.

Fix: Set Cloudflare to Full (Strict), or temporarily disable orange-cloud proxying until Caddy obtains the initial certificate. Verify port 80 is open in UFW.

3. "Port 80 or 443 already in use during setup"

Cause: An existing web server (Apache, Nginx, or Plesk) is running on the fresh VPS image.

Fix: Disable the conflicting web server:

sudo systemctl stop nginx apache2 2>/dev/null || true
sudo systemctl disable nginx apache2 2>/dev/null || true
sudo systemctl restart agent-stack.service

4. "Lost or forgotten database passwords"

Fix: Credentials are saved in /opt/agent-stack/.env. Inspect them with:

sudo cat /opt/agent-stack/.env | grep -E 'PASSWORD|SECRET'

5. "How do I safely prune Docker disk space without losing data?"

⚠️
Caution: Never run docker volume prune -a. Use the safe command below: 
# Safely cleans stopped containers and dangling images; preserves named volumes
docker system prune -af
